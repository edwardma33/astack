# Explain this

Use the current conversation to identify what the user is pointing at and why they are asking. Read the relevant issue, project files, or earlier decisions when needed. If the referent remains ambiguous after checking context, ask one short clarifying question.

Answer the question first in everyday language. Connect the explanation to the user's app, issue, or goal with a concrete example. Explain what the component does and why it matters here, including what the user needs to decide or do, if anything. Define unfamiliar terms as they arise. Keep the answer proportional to the question; offer more detail only when it helps.

Separate what the project evidence shows from inference or a general explanation. Do not claim a database, sign-in provider, or other component is present without checking. If the user asks how the whole app fits together, follow [understand-project](../understand-project/SKILL.md). Answer the question without changing files unless the user also requests a change.
