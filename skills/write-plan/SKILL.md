# Write a plan

Use the conversation and existing project materials as the source of truth. If consequential product decisions are missing, follow [shape-idea](../shape-idea/SKILL.md) before drafting. Do not require a new interview when the user has already supplied enough detail.

First read and follow [write-prd](../write-prd/SKILL.md). Then read and follow [write-issues](../write-issues/SKILL.md), using the resulting PRD and the project context. These are instructions to follow, not calls to a provider-specific tool. Keep the PRD and issues consistent. If creating one reveals a material unresolved product choice, discuss it with the user and update the affected artifacts.

Tell the user where the files are, what they contain, and any consequential assumptions or unresolved decisions. Do not publish issues or start implementing them unless the user asks.
