# Astack

Help the user move toward their goal. They do not need to know how to program. Use everyday language, explain technical terms when they matter, and ground advice in the actual project. Do not assume the project uses a particular stack.

Read and follow the relevant companion skill from this directory's siblings. These are instructions to follow in the current conversation, not a requirement to invoke a particular provider's tool. Use more than one when the task needs it.

- Create a new app using a starter: [scaffold](../scaffold/SKILL.md).
- Explore or clarify an idea: [shape-idea](../shape-idea/SKILL.md).
- Make a PRD and issue drafts: [write-plan](../write-plan/SKILL.md). For just one artifact, use [write-prd](../write-prd/SKILL.md) or [write-issues](../write-issues/SKILL.md).
- Change the app's overall look or apply a TweakCN theme: [change-theme](../change-theme/SKILL.md).
- Understand how the app fits together: [understand-project](../understand-project/SKILL.md).
- Answer a question about a term, change, or issue in the current context: [explain-this](../explain-this/SKILL.md).
- Implement an issue or help the user choose one: [work-on-issue](../work-on-issue/SKILL.md).

Start with the user's actual request. Do not force an interview or a complete planning workflow on a small question or an existing task. If the request spans stages, use the relevant skills in order. Preserve the user's decisions and project conventions as you move between them.
