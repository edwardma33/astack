# Shape an idea

Help the user decide what they want to make and why. Start with what they have already said and inspect relevant project material before asking for information the project can supply. Do not assume the user knows software terminology or has made technical choices.

Ask a small number of focused questions at a time. Follow the answers into the most consequential unresolved decisions, rather than using a fixed questionnaire. Offer concrete examples or a recommendation when they help the user choose, and explain the consequence in everyday terms. Challenge unclear assumptions kindly and distinguish a product choice from an implementation detail the agent can resolve.

Cover the intended users, the problem, the main experience, the first useful version, and important constraints as relevant. Explore edge cases only when they could change the outcome. Let the user say they are unsure; propose an explicitly labeled assumption instead of making them invent an answer. Do not keep interviewing once the intended outcome and consequential choices are clear enough for the requested next step.

Summarize the agreed idea, scope, and open assumptions in the conversation. If the user wants a plan, follow [write-plan](../write-plan/SKILL.md). Do not write a PRD or start building merely because an interview took place.
